# Build and deploy with STM32CubeIDE

Import `STM32CubeIDE` from this project and build `Debug`. The target is fixed
to STM32H723VET6 and both CubeIDE configurations use `-O2`.

The production peripheral configuration is:

```text
PB0            COMP1_INP, analog input from the AGC/front end
DAC1_CH1       internal COMP1 threshold
COMP1          IN+ PB0, IN- DAC1_CH1, high-speed, low hysteresis
TIM2 CH4       internal COMP1 route, both edges, 32-bit circular DMA
PE9/TIM1 CH1   optical TX generated by DMA2
PB10/PB11      USART3 TX/RX to the Raspberry Pi, 2 Mbaud
```

`HAL_TIMEx_TISelection(... TIM_TIM2_TI4_COMP1 ...)` selects the internal
comparator route; PC5 is not required. ADC1 and TIM6 are not initialized.

Keep I-cache and D-cache enabled. The TIM2 timestamp ring is in the dedicated
non-cacheable `.dma_ring` MPU region. TX DMA slots are cacheable and explicitly
cleaned before DMA starts.

Build from PowerShell if desired:

```powershell
cd Z:\Projects\Sunrise\communications\openvlc\firmware-v2
.\tools\build_cubeide_debug.ps1
```

The ELF is:

```text
STM32CubeIDE/Debug/firmware-v2.elf
```

After CubeMX regeneration, verify PB0, low comparator hysteresis, TIM2 CH4
both-edge capture, the internal COMP1 selection, word-aligned circular DMA,
and that generated code did not re-enable ADC1 or TIM6 in `main.c`.

The initialization log must identify `COMP1_PB0`, the selected profile, the
TIM2 capture rate, host baud, and enabled caches. During traffic require
`ringdrop=0` and no hardware overcapture before evaluating decoder quality.
